# Расчёты, возвраты и повторные запросы — этап 3

Сделано локально, без деплоя на VPS.

- Итог продажи рассчитывается только по ценам из базы.
- Скидка позиции и общая скидка складываются один раз; скидка не может быть
  больше стоимости товаров.
- Для наличных разрешена сдача; для карты, Kaspi QR и смешанной оплаты нужна
  точная сумма чека.
- Остаток списывается атомарно и не уходит ниже нуля.
- Продажа получает `client_sync_id`. Повтор того же запроса возвращает тот же
  чек и не списывает товар повторно. Тот же ключ с изменёнными данными даёт 409.
- Складские операции API и обычная форма используют тот же механизм ключей.
- Возврат блокируется на время операции, проверяет статус чека и возвращает
  товары ровно один раз. Повторный возврат не увеличивает остаток повторно.
- Чек после удаления нельзя повторно создать тем же ключом.
- Печать не запускается повторно при повторном ответе API.

Добавлена миграция `sales/0006_financial_operation_receipts.py`; при деплое
нужно выполнить обычный `python manage.py migrate`. Новая таблица хранит только
технический ключ повтора, его хеш, пользователя и ссылку на результат.

Проверка: целевые тесты расчётов, возврата, ролей, входа, мониторинга и печати
проходят (`81 tests`, включая Telegram webhook).
