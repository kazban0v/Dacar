# Права доступа — этап 2 (локально)

Изменения не применены к VPS. Развёртывать вместе с настройками этапа 1:
см. `login-security.md`. Миграции не нужны, роли существующих пользователей
автоматически не меняются.

## Границы

| Функция | Кассир | Администратор магазина | Суперпользователь |
| --- | --- | --- | --- |
| Касса, поиск товаров, просмотр склада | Да | Да | Да |
| Чеки и печать | Только свои | Все | Все |
| Возврат / удаление чека | Нет | Да | Да |
| Создание / изменение товара, складские операции, категории | Нет | Да | Да |
| Аналитика, экспорт, AI, аудит | Нет | Да | Да |
| Управление обычными сотрудниками | Нет | Да | Да |
| Изменение технических аккаунтов через штат | Нет | Нет | Да, кроме себя и защищённого владельца |
| Django admin | Нет, даже при is_staff | Только с is_staff и разрешениями моделей | С is_staff |
| Мониторинг сервера | Нет | Нет | Да, через Django admin |

`is_superuser` по-прежнему сильнее бизнес-роли CASHIER. Существующий
суперпользователь не становится обычным кассиром от изменения поля role.
Технические флаги не выдаются через форму «Персонал». Обычный администратор
с правом users.change_user также не может выдать их через Django admin,
сменить пароль суперпользователя или удалить защищённый аккаунт массовым действием.
Персональные права и группы пользователя там доступны на изменение только
суперпользователю. Модели и их обычные CRUD-экраны сохранены.

Публичная регистрация остаётся выключенной по конфигурации; если её явно
включить, новый аккаунт получает только CASHIER, независимо от POST-полей.
Неподдерживаемая роль MANAGER больше не разрешает возврат.

Ключевой обход закрыт: `/catalog/api/stock-action/` и `/m/catalog/api/stock-action/`
проверяют администратора до чтения операции, UUID повтора или изменения остатков.
На мобильном складе кассиру не показываются действия изменения.

Проверены изоляция чеков, печать чужих чеков, API аналитики, уведомления
только текущего пользователя, неактивные сессии, повышение привилегий,
защита технических аккаунтов и сохранение рабочих действий администратора.

## Проверка

`python manage.py test users.test_permissions config.test_security_settings users.test_login_security config.test_monitoring sales.test_receipts sales.tests --noinput`

Не запускать общий поиск тестов: корневой `test_all_features.py` меняет
данные при импорте. Здесь используется только отдельная тестовая БД.

Корректность расчётов, возвратов и повторных запросов, а также история
мониторинга и уведомления реализованы отдельными локальными этапами.
Закупочные цены и маржа доступны только администратору: это проверяется и в
шаблонах, и в API, включая прямые запросы кассира.
